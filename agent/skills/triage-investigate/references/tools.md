# Triage tool catalog

Company-service tools use Executor. Use `connection_search` with the `connection` argument set to the Executor connection named in this turn's access instructions. Inside `execute`, search one provider namespace with `tools.search({ namespace, query })`, inspect `tools.describe.tool({ path })`, and call the returned `tools[path](input)`. Check `result.ok` before reading `result.data`. The provider tool names below are search hints, not callable Executor addresses. Never guess paths or use a removed direct provider connection. Authored Foreman helpers keep their bare names and require no discovery.

## Instantly evidence bounds

Both authored helpers validate the complete accepted membership set before returning evidence. Find workspaces with `list_instantly_subworkspaces({ search: "customer name fragment" })`; no internal ID is needed. Search is a literal, case-insensitive name match. Results contain at most `limit` entries (default 20, maximum 100, also bounded to 256 KiB), `totalMatches`, `totalAcceptedSubworkspaces`, and `nextStartingAfter`. Continue with the same search and returned cursor until null when more candidates need review; `{}` browses a bounded first page. `membershipComplete` describes internal validation, not whether this public page contains every match. Choose the evidence-backed candidate and pass its returned ID to `read_instantly_subworkspace`; do not guess between ambiguous names or equate a product display name with provider identity. A 100-page source cap means membership is incomplete and the lane could not run. Zero search matches prove only that this name fragment did not resolve, not absent provisioning. Try other evidence-backed names or the linked provider ID in the pinned production scope; if identity remains unknown, mark provider resource state unverified. A matched, successful resource read may return valid empty results.
